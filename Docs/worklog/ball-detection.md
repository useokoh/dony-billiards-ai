# 공 인식

## 2026-11-09 샷 영상 길이를 공이 멈출 때까지로 변경
- 한 일: 샷 영상을 샷 시작 1초 전부터 공이 모두 멈춘 1초 뒤까지 자르도록 바꾸고 219개를 다시 만들었다. 샷 JSON에 `rest_sec`(실제 멈춘 시간)을 추가했다. 테스트 63개 통과.
- 결정과 이유: 사용자가 10초 고정 대신 공이 멈출 때까지를 선택했다. 10초로는 176개 샷이 공이 멈추기 전에 끝났다.
- 문제와 해결: 움직임 구간의 끝을 그대로 쓰니 영상 끝 1초에도 공이 30~40px 움직였다. 구간 판정은 프레임당 약 1.8px 미만을 멈춤으로 봐서 천천히 구르는 공을 놓친다. 15프레임 동안 모든 공의 이동이 3px 이하인 시점을 따로 찾게 했다(구간 끝 뒤 0.4~1.9초).
- 바뀐 파일: `analyzer/clips.py`, `analyzer/shots.py`, 테스트, `README.md`, `Docs/기술스택.md`, `Docs/당구장_AI_경기분석_창업기획서.md`
- 확인 결과: 영상 길이 7.6~18.2초(중앙값 13.6초), 30초 제한에 걸린 영상 0개, 마지막 충돌이 영상 밖인 샷 0개, 총 685MB. 끝 1초 동안 4px 넘게 움직인 영상은 44개이며 최대 5.1px라 거의 멈춘 상태이다.

## 2026-11-02 4단계 이닝 정리와 샷별 10초 영상
- 한 일: `analyzer/innings.py`, `analyzer/clips.py`를 만들어 샷에 이닝, 선공·후공, 순번을 붙이고 샷별 10초 영상을 저장했다. 테스트는 총 60개 통과.
- 결정과 이유: 수구가 바뀌면 다음 선수 차례로, 영상의 첫 샷을 친 선수를 선공으로 본다. 시작점을 맞추기 위해 복사 대신 재인코딩하고 소리는 뺐다.
- 바뀐 파일: `analyzer/`, `README.md`, `data/results/clips/`(Git 제외)
- 확인 결과:
  - 영상1 102샷 25이닝, 영상2 117샷 30이닝. 영상 219개 모두 열리고 길이 9.97~10.00초, 총 547MB
  - 표본 50개에서 수구 출발 시점은 예상보다 중앙값 0.07~0.10초 늦었다(최대 0.67초). 이동 6px 기준으로 잰 값이다.
  - 전체 샷 중 176개는 공이 멈추기 전에 10초 영상이 끝나고, 7개는 마지막 충돌도 영상 뒤에 있다. 길이 결정은 사용자 확인 필요.
  - 이닝 수는 실제 경기 기록과 비교하지 않았다. 샷을 하나 잘못 잡으면 이후 이닝 번호가 밀릴 수 있다. 두 영상이 같은 경기인지도 미확인이며 각각 1이닝부터 센다.

## 2026-11-02 사용자 확인 결과로 판정 수정
- 한 일: 사용자가 영상으로 확인한 샷 15개를 `analyzer/tests/data/reviewed_shots.json`에 저장하고 실제 영상 회귀 테스트로 만들었다. 확인 영상과 입력 페이지는 `Project/HTML/득점판정_확인/`에 있다.
- 결정과 이유:
  - 공이 붙어 보여도 안 맞은 경우가 많다. 멈춰 있던 목적구는 전후 위치가 4px 이상 달라졌을 때만 충돌로 인정한다.
  - 수구가 목적구에 붙어 멈추면 충돌로 인정한다. 아주 느린 충돌은 목적구가 밀리지 않기 때문이다.
  - 수구가 거의 안 움직이거나, 위치 대부분이 추정이거나, 3초 미만이고 충돌·쿠션이 없으면 샷에서 제외한다.
- 문제와 해결: 이전 기록의 "공이 실제로 닿는 모습이 보였다"는 판단은 틀렸다. 8건 중 6건은 사용자가 안 맞았다고 확인했다.
- 확인 결과: 아래 3단계 항목의 수치는 수정 전 값이며, 최신 값은 이 항목과 실행 결과를 따른다. 확인한 15개 중 13개가 판정과 일치한다.
  - 해결하지 못한 2건: 영상2-샷62(수구와 빨간공의 측정 거리가 54px이고 빨간공이 밀리지 않음), 영상2-샷65(빨간공 충돌과 쿠션이 거의 같은 프레임이라 쿠션 1회를 분리하지 못함)
  - 15개는 불일치 샷만 고른 것이라 전체 정확도가 아니다.
  - 최신 수치: 샷 102개, 117개(샷이 아닌 구간 3개 제외). 다음 차례와 일치 101/101, 113/116, 합계 214/217(98.6%)
  - 남은 불일치 3건: 영상2 1296.0초, 1745.8초, 1833.4초. 1296.0초는 충돌 기준을 3px에서 4px로 올리며 새로 생겼다.
  - 기준을 같은 두 영상에 맞춰 조정했으므로 이 수치는 새 영상의 정확도를 보장하지 않는다. 다른 날 찍은 영상으로 검증이 필요하다.

## 2026-11-02 3단계 샷·쿠션 판정
- 한 일: `analyzer/shots.py`를 만들어 움직임 구간마다 수구, 쿠션 횟수, 충돌 순서, 두 번째 목적구 전 쿠션 수, 득점 후보를 JSON으로 저장한다. 테스트는 총 35개 통과.
- 결정과 이유: 다음 샷의 수구는 판정과 별개의 정보라, 득점 후보와 차례 유지가 맞는지를 검증 기준으로 썼다. 수치를 더 맞추려 기준을 무리하게 조정하지 않았다.
- 문제와 해결: 처음 일치율은 79%, 78%였다. 빠른 공의 충돌 거리를 속도에 비례해 넓히고, 멈춰 있던 공이 움직이기 시작한 시점과 살짝 밀린 경우를 충돌 판정에 추가했다.
- 확인 결과:
  - 샷 104개, 118개. 차례와 일치 99/103(96%), 104/117(89%), 합계 203/220(92%)
  - 득점 후보인데 수구가 바뀐 8건은 해당 프레임에서 공이 실제로 닿는 모습이 보였다. 차례가 바뀐 이유는 영상만으로 확정하지 못했으며 사람 확인이 필요하다.
    - 영상1: 991.9초, 2384.3초 / 영상2: 96.8초, 771.3초, 853.6초, 881.0초, 1720.6초, 3311.4초
  - 득점 후보가 아닌데 수구가 유지된 경우 일부는 쿠션을 적게 셌거나 충돌을 놓친 것으로 보이나 개별 원인은 확정하지 않았다.
  - 알려진 한계: 각 영상 첫 구간(1.5초 내외, 충돌 없음)은 실제 샷이 아닐 수 있다. 두 공이 같은 프레임에 움직이면 수구 판별이 흔들릴 수 있다(근소한 차이 17건). 쿠션 수는 차례 기준으로 간접 확인만 했고 사람이 센 정답과 비교하지 않았다.

## 2026-11-02 2단계 영상 전체 궤적 추적
- 한 일: `analyzer/track.py`를 만들어 영상 전체의 공 좌표를 병렬 처리로 기록하고, 공백 채우기, 튄 값 제거, 움직임 구간 찾기, 경로 그림 저장을 구현했다. 테스트는 총 22개 통과.
- 결정과 이유: 짧게 튄 묶음(30프레임 미만이고 앞 위치와 끊김)은 공이 아닌 것으로 지운다. 공 이동 한계는 프레임당 안쪽 면 너비의 12%이다.
- 문제와 해결:
  - 큐에 붙어 멈춘 흰공을 놓치던 문제를 두께 기반 탐지로 고쳤다. 150장면씩 재검사에서 놓친 것은 가려진 2장면뿐이다.
  - 흰공이 한순간 다른 흰 물체로 튀던 구간은 튄 값 제거로 없앴다.
- 확인 결과:
  - 48.3분 영상 4.6분, 58.2분 영상 5.6분 처리. 공별 직접 검출률은 99.4% 이상
  - 움직임 구간 104개, 118개이고 길이 중앙값은 10.2초. 샷 수와 일치하는지는 미검증
  - 움직이는 공을 표본으로 295개 잘라 봤을 때 실제 공 위치였고, 추정 프레임 3개는 번진 공이 중심에서 약간 벗어남
  - 2474초 구간은 프레임별 실제 장면과 경로가 일치
  - 알려진 한계: 구간 단위 탐색 때문에 프레임이 최대 2프레임(약 0.07초) 어긋날 수 있음. 4단계의 10초 영상에서 다시 확인 필요
  - 가장 긴 추정 공백은 259프레임(빨간공)이며 개별 장면은 확인하지 않음
