# 기술 결정

## 2026-11-02 이닝 기준 확정
- 결정과 이유: 사용자가 실제 대회 경기 룰을 쓰기로 했다. 선공과 후공이 한 번씩 차례를 마치면 1이닝이다. 수구가 바뀌는 시점으로 선수 차례를 구분할 수 있다.
- 바뀐 파일: `Docs/기술스택.md`, `Docs/당구장_AI_경기분석_창업기획서.md`
- 확인 결과: 문서만 수정했다. 실제 영상의 이닝 판별 정확도는 미검증이다.

## 2026-11-02 1~2시간 영상 자동 정리와 샷 분석으로 요구사항 변경
- 결정과 이유:
  - 사용자가 짧은 테스트 영상이 아니라 1~2시간 경기 영상을 올리면 이닝과 샷으로 자동 정리되어야 한다고 정했다.
  - 샷을 고르면 실제 경로, 10초 영상, 실패 원인, 최적 경로를 보여준다.
  - 이닝은 수구 변경으로 나누고, 영상 자르기는 FFmpeg, 실패 원인은 3쿠션 규칙 기반으로 설계했다.
  - 최적 경로는 회전과 힘을 알기 어려워 시제품에서는 참고 경로로 표현했다.
- 바뀐 파일: `Docs/기술스택.md`, `Docs/당구장_AI_경기분석_창업기획서.md`
- 확인 결과: 문서만 수정했다. 이닝 정확도, 처리 시간, 추천 경로 품질은 미검증이다. 홈 화면 초안에는 아직 반영하지 않았다.

## 2026-11-02 프론트엔드 Next.js, 백엔드 NestJS로 변경
- 결정과 이유:
  - 사용자가 프론트엔드는 Next.js, 백엔드는 NestJS로 정했다. FastAPI와 순수 HTML 계획은 대체한다.
  - 공 인식은 OpenCV 자료가 풍부한 Python으로 유지한다. NestJS가 별도 프로세스로 실행한다.
  - 분석 프로그램은 JSON만 만들고, DB 저장은 NestJS가 맡는다.
  - 장단점을 비교한 뒤 사용자가 공 인식 Python 유지와 Prisma 사용을 확정했다.
- 바뀐 파일: `Docs/기술스택.md`, `Docs/당구장_AI_경기분석_창업기획서.md`
- 확인 결과: 문서만 수정했고 설치와 실행은 하지 않았다. Node.js 버전 호환성은 0단계에서 확인해야 한다.

## 2026-10-19 웹과 SQLite 결정
- 결정과 이유:
  - 이용자 화면은 웹으로 만든다. 설치 없이 열 수 있고 기존 앱에 웹뷰로 붙이기 쉽다.
  - 데이터베이스는 SQLite를 쓴다. 영상 파일은 폴더에 저장하고 DB에는 위치와 시간만 기록한다.
  - 대상 종목은 3구(3쿠션)이다. 1인 개발, Mac 실행 기준이며 문서와 코드를 함께 제출한다.
- 바뀐 파일: `Docs/당구장_AI_경기분석_창업기획서.md`, `Docs/기술스택.md`
- 확인 결과: 공 인식 정확도는 아직 실제 영상으로 검증하지 않았다.
