# 앱 디자인

## 2026-11-09 스플래시 화면 구현
- 한 일: 앱 접속 시 약 2.9초 스플래시를 웹에 구현했다. 흰 공이 빨간 공 → 쿠션 3번 → 노란 공 순서로 득점하는 빛 궤적을 그리고, 득점 순간 번쩍인 뒤 "Dony" 글자가 하나씩 떠오르고, 로고 쪽으로 확대되며 홈이 열린다.
- 결정과 이유: 사용자가 3쿠션 궤적 콘셉트, 로고 글자 "Dony", 브라우저 창마다 1번 보여 주기를 골랐다. 넷플릭스 로고·효과음은 따라 하지 않고 확대 전환 연출만 참고했다. 색·글꼴은 블루 시안 기준안(배경 #101315, 천 #123F60, 강조 #6CBDEB, IBM Plex Sans KR)을 따랐다.
- 바뀐 파일: `web/src/components/splash/`(Splash.tsx, Splash.module.css, timeline.ts, guard.ts), `web/src/app/layout.tsx`
- 문제와 해결:
  - "use client" 파일의 문자열 상수를 서버 레이아웃이 가져오면 값이 아니라 참조가 넘어가서 `guard.ts`로 분리했다.
  - 다시 열 때 스플래시가 잠깐 보이는 문제는 `<head>` 인라인 스크립트가 첫 화면 전에 `data-splash="done"`을 붙이고 CSS로 숨기는 방식으로 막았다(Next 문서 preventing-flash-before-hydration 방식).
  - 자바스크립트가 멈춰도 6초 뒤에는 CSS가 스플래시를 치운다.
  - 첫 빌드는 Google 글꼴 받기 오류(module-not-found)로 실패했고 다시 빌드하니 통과했다.
- 확인 결과: 타입 검사, ESLint, 빌드 통과. 헤드리스 Chromium(390×844)으로 0.5~3.3초를 캡처해 순서대로 나오는 것을 확인했다. 새로고침 시 숨김, 건너뛰기 버튼, 화면 누르기, 움직임 줄이기(로고만 0.8초)도 확인했다. 실제 휴대폰과 Safari는 확인하지 않았다. 확인 중에 기존 3000번 개발 서버가 꺼져 있었다.

## 2026-11-02 휴대폰 웹 화면 전체 시안
- 한 일: 기획서 8장과 기술스택 7장을 기준으로 7개 화면을 새 캔버스에 만들었다. 경기 목록, 리플레이, 샷 피드백, 영상 올리기, 모서리 지정, 분석 중, 분석 실패다.
- 결정과 이유: 사용자가 이 블루 시안을 기준안으로 선택했다(이전 검정·빨강 초안은 기준에서 제외). 사용자가 디자인 시스템 대신 앱 전용 룩을 선택했다. 기록 도구 느낌의 어두운 화면에 파란 당구대와 초크 파랑 강조색을 썼고, 공 3색은 궤적 구분에만 쓴다. 앱 메뉴 없이 웹 화면으로 설계했다. 분석 진행은 API의 상태값에 맞춰 3단계로만 표시한다.
- 바뀐 파일: 디자인 캔버스 https://claude.ai/artifact/Xjzjk6CGGBPai7fmHxTwzV (프로젝트 코드 파일 변경 없음)
- 확인 결과: 렌더링과 동작은 직접 확인하지 않았다. 경기·궤적은 예시 데이터이고 영상 자리는 당구대 그림이다. 모서리 핸들은 끌리지 않는다. "두 번째 목적구 충돌이 확인되지 않았습니다" 문구는 문서에 없어 새로 제안한 것이다.

## 2026-11-02 앱 형태 홈 화면 초안
- 한 일: 기획서를 바탕으로 390×844 휴대폰 크기의 홈 화면 초안을 디자인 캔버스에 만들었다. 구성은 최근 경기 궤적, 리플레이, 경기 요약, 샷 피드백, 영상 업로드, 하단 메뉴 3개다.
- 결정과 이유: 사업소개서 v3의 검정·빨강 톤을 이어 갔다. 디자인 시스템은 사용자가 쓰지 않기로 했다.
- 바뀐 파일: 디자인 캔버스 https://claude.ai/artifact/Ab9UmPembXf7cVntHBVbXL (프로젝트 코드 파일 변경 없음)
- 확인 결과: 렌더링 화면은 직접 확인하지 않았다. 서비스명, 경기 날짜, 당구대 이름은 빈칸이고, 12·4·2.6은 기술스택 문서의 예시 값이다. 버튼은 아직 동작하지 않는다.
