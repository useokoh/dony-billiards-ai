- 한 일: 경기 상세에 "샷 영상 / 경로 그림" 전환과 "코칭" 탭을 추가했다. 경로 그림(`TableView.tsx`)은 당구대 SVG에 공별 실제 경로(실선), 시작·멈춘 위치, 고른 추천 경로(점선과 쿠션 순번)를 그린다. 코칭 탭(`CoachingPanel.tsx`)은 선수 기준 / 초급 20 / 중급 27 / 고급 27+ 중 하나를 골라 추천 경로 카드(첫 목적구·두께, 쿠션 순서·방향, 권장 회전·당점, 권장 강약, 이유, 계산 신뢰도)와 코칭 문장을 보여 준다. 상단에서 선공·후공 선수를 연결하고, `/players`에서 선수를 추가하고 핸디를 고친다. 경기 목록 아래에 "선수 관리" 링크를 넣었다.
- 결정과 이유: 권장값이 실제 판정처럼 보이지 않도록 카드 라벨을 "권장 회전·권장 강약"으로 쓰고 아래에 안내문을 항상 둔다. 득점한 샷은 코칭 대신 "실패한 샷에만 제공"을 보여 준다.
- 바뀐 파일: `web/src/components/match/`(TableView, CoachingPanel 새로 만듦, MatchDetail, match.module.css), `web/src/app/players/`(새로 만듦), `web/src/app/page.tsx`, `web/src/lib/api.ts`
- 확인 결과: tsc, eslint, `next build` 통과(`/players` 정적 페이지 생성). 브라우저·휴대폰 화면은 아직 보지 않았다.

## 2026-11-09 스플래시 hydration 경고 수정
- 문제와 해결: 개발 서버에서 "A tree hydrated but some attributes … didn't match" 경고가 났다. 빨간 공 `cy`가 서버 `43.201037725663404`, 브라우저 `43.20103772566341`로 달랐다. `timeline.ts`의 `Math.hypot`이 Node와 Chrome에서 마지막 자리가 다르게 나오기 때문이다. 목적구 좌표를 소수 셋째 자리에서 반올림(`round3`)해 같은 값으로 맞췄다. 다른 좌표(레일 점, 경로)는 정수나 단순 덧셈이라 해당 없다.
- 바뀐 파일: `web/src/components/splash/timeline.ts`
- 확인 결과: 타입 검사, ESLint 통과. 3000번 `next dev`의 서버 HTML에서 `cx="84.234" cy="43.201"`로 나오는 것을 확인했다. 브라우저 콘솔에서 경고가 사라졌는지는 직접 보지 않았다. 사용자가 dev 서버를 쓰는 중이라 빌드는 하지 않았다.

## 2026-11-09 경기 목록·경기 상세 화면을 API에 연결
- 한 일: `/`를 경기 목록으로 바꾸고, 기존 개발 환경 점검 화면은 `/health`로 옮겼다. `/matches/[id]` 경기 상세를 만들었다. 위에는 선택한 샷 영상, 아래에는 [샷 목록 N] [N이닝 N번째 샷 피드백] 탭이 있다. 피드백 탭에는 두 번째 공 전 쿠션 수, 첫 충돌 공, 사건 순서(빨간공 → 쿠션 → …), 7.1 피드백 문장, 인정/불인정 버튼, 이전·다음 샷을 둔다.
- 결정과 이유:
  - 블루 시안(Main, Replay, Feedback 대지)의 색, 간격, 탭 구조를 따랐다. 궤적 데이터가 아직 없어서 시안의 당구대 그림 자리에 실제 샷 영상을 넣었다. 목록 카드의 궤적 썸네일과 "경기 영상 올리기" 버튼은 기능이 없어서 넣지 않았다.
  - 글꼴은 빌드 때 내려받지 않도록 시스템 한글 글꼴(Apple SD Gothic Neo 등)을 쓴다. Google 글꼴 오류는 [environment](environment.md) 참고.
  - 샷 목록은 시안의 단순 목록에 이닝 구분 머리글(이닝 점수 포함)을 더했다.
  - 동적 주소(`/matches/[id]`)는 `cacheComponents` 때문에 `useParams`를 쓰는 화면을 Suspense로 감쌌다(Next 문서 use-params.md).
  - API 포트는 `NEXT_PUBLIC_API_PORT`(기본 4000)로 바꿀 수 있게 했다. 테스트 서버를 따로 띄우기 위해서다.
- 바뀐 파일: `web/src/app/page.tsx`(새로 씀), `web/src/app/health/page.tsx`(옮김), `web/src/app/home.module.css`, `web/src/app/matches/[id]/page.tsx`, `web/src/components/match/`(MatchDetail, ShotList, ShotFeedback, match.module.css), `web/src/lib/`(api.ts, shot-text.ts), `web/src/app/globals.css`(시안 색 변수, 어두운 화면 고정)
- 문제와 해결:
  - effect 안에서 바로 setState를 부르면 ESLint(react-hooks/set-state-in-effect) 오류가 나서, 잘못된 경기 번호는 렌더링 중에 판단하게 바꿨다.
  - **사용자가 터미널에서 `npm run start`(3000번)를 실행 중일 때 `npm run build`를 하면 그 서버가 깨진다**(화면 파일 500 오류). 빌드 결과를 다시 쓰기 때문이다. 확인 빌드는 실행 중인 서버를 끄고 하거나, 사용자에게 다시 실행을 부탁해야 한다.
- 확인 결과: 타입 검사, ESLint, 빌드 통과. DB 사본 API(4010) + 웹(3010)을 헤드리스 Chrome(390×844, 휴대폰 모드)으로 확인했다. 목록 카드 2개, 상세 이동, 샷 영상 1920×1080 로드·재생·8초로 이동, 2이닝 샷 선택과 피드백 탭, 인정 → 점수 1:0과 목록 "인정" 표시, 다시 눌러 취소 → 0:0, 다음 샷, 없는 경기 안내, PC 1280폭 가로 스크롤 없음까지 확인했다. 실제 휴대폰과 Safari는 확인하지 않았다.
- 참고: 분석기가 샷 절반 이상(102개 중 54개, 117개 중 55개)을 득점 후보로 표시하고 있어서, 사람이 확인할 양이 많다.

## 2026-11-09 스플래시 화면 구현
- 한 일: 앱 접속 시 약 2.9초 스플래시를 웹에 구현했다. 흰 공이 빨간 공 → 쿠션 3번 → 노란 공 순서로 득점하는 빛 궤적을 그리고, 득점 순간 번쩍인 뒤 "Dony" 글자가 하나씩 떠오르고, 로고 쪽으로 확대되며 홈이 열린다.
- 결정과 이유: 사용자가 3쿠션 궤적 콘셉트, 로고 글자 "Dony", 브라우저 창마다 1번 보여 주기를 골랐다. 넷플릭스 로고·효과음은 따라 하지 않고 확대 전환 연출만 참고했다. 색·글꼴은 블루 시안 기준안(배경 #101315, 천 #123F60, 강조 #6CBDEB, IBM Plex Sans KR)을 따랐다.
- 바뀐 파일: `web/src/components/splash/`(Splash.tsx, Splash.module.css, timeline.ts, guard.ts), `web/src/app/layout.tsx`
- 문제와 해결:
  - "use client" 파일의 문자열 상수를 서버 레이아웃이 가져오면 값이 아니라 참조가 넘어가서 `guard.ts`로 분리했다.
  - 다시 열 때 스플래시가 잠깐 보이는 문제는 `<head>` 인라인 스크립트가 첫 화면 전에 `data-splash="done"`을 붙이고 CSS로 숨기는 방식으로 막았다(Next 문서 preventing-flash-before-hydration 방식).
  - 자바스크립트가 멈춰도 6초 뒤에는 CSS가 스플래시를 치운다.
  - 첫 빌드는 Google 글꼴 받기 오류(module-not-found)로 실패했고 다시 빌드하니 통과했다.
- 확인 결과: 타입 검사, ESLint, 빌드 통과. 헤드리스 Chromium(390×844)으로 0.5~3.3초를 캡처해 순서대로 나오는 것을 확인했다. 새로고침 시 숨김, 건너뛰기 버튼, 화면 누르기, 움직임 줄이기(로고만 0.8초)도 확인했다. 실제 휴대폰과 Safari는 확인하지 않았다. 확인 중에 기존 3000번 개발 서버가 꺼져 있었다.

## 2026-11-02 휴대폰 웹 화면 전체 시안
- 한 일: 기획서 8장과 기술스택 7장을 기준으로 7개 화면을 새 캔버스에 만들었다. 경기 목록, 리플레이, 샷 피드백, 영상 올리기, 모서리 지정, 분석 중, 분석 실패다.
- 결정과 이유: 사용자가 이 블루 시안을 기준안으로 선택했다(이전 검정·빨강 초안은 기준에서 제외). 사용자가 디자인 시스템 대신 앱 전용 룩을 선택했다. 기록 도구 느낌의 어두운 화면에 파란 당구대와 초크 파랑 강조색을 썼고, 공 3색은 궤적 구분에만 쓴다. 앱 메뉴 없이 웹 화면으로 설계했다. 분석 진행은 API의 상태값에 맞춰 3단계로만 표시한다.
- 바뀐 파일: 디자인 캔버스 https://claude.ai/artifact/Xjzjk6CGGBPai7fmHxTwzV (프로젝트 코드 파일 변경 없음)
- 확인 결과: 렌더링과 동작은 직접 확인하지 않았다. 경기·궤적은 예시 데이터이고 영상 자리는 당구대 그림이다. 모서리 핸들은 끌리지 않는다. "두 번째 목적구 충돌이 확인되지 않았습니다" 문구는 문서에 없어 새로 제안한 것이다.
