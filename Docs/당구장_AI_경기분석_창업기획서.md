# 당구장 AI 경기 분석 서비스 창업 기획서

## 1. 아이템의 주제

당구 경기 영상을 AI로 분석해 경기 기록과 실력 향상 피드백을 제공하는 **AI 기반 당구 경기 분석 서비스**를 개발한다. 대형 당구장 프랜차이즈 본사와 기존 당구장 솔루션 기업을 주요 판매 대상으로 삼고, 현장 검증을 거쳐 여러 매장으로 확대하는 것을 목표로 한다.

## 2. 고객

- **주요 고객:** 대형 당구장 프랜차이즈 본사 및 다수의 당구장을 운영하는 기업
- **기업 고객:** 기존 당구장 점수판·관리 시스템을 운영하거나 공급하는 솔루션 기업
- **최종 이용자:** 자신의 경기 내용을 확인하고 플레이를 개선하고 싶은 당구 이용자

## 3. 문제점

- 당구 이용자가 자신의 경기 내용을 체계적으로 돌아보고 분석하기 어렵다.
- 경기 영상이 제대로 기록되지 않거나 필요한 장면을 다시 확인하기 불편할 수 있다.
- 점수 기록만으로는 공의 움직임이나 플레이 과정에서 개선할 점을 파악하기 어렵다.
- 당구장 운영 시스템은 고객·매출 관리 등 일반적인 기능에 집중할 수 있어, AI 경기 분석이라는 전문 기능을 중심으로 차별화할 기회가 있다.

> 위 문제는 사업 아이디어에서 설정한 가설이다. 실제 고객 인터뷰와 경쟁 서비스 조사를 통해 문제의 크기와 기존 서비스의 제공 기능을 확인해야 한다.

## 4. 솔루션

- **경기 영상 분석:** 카메라로 촬영한 경기 영상을 분석해 경기 장면과 플레이 기록을 확인할 수 있도록 한다.
- **AI 기반 피드백:** 경기 데이터를 바탕으로 이용자가 자신의 플레이를 돌아보고 개선점을 파악하도록 돕는다.
- **경기 리플레이:** 경기 영상을 저장하고 주요 장면을 다시 확인할 수 있도록 한다.
- **단계적 개발:** 처음부터 모든 기능을 구현하기보다 핵심 분석 기능을 시제품으로 만들고, 실제 당구장에서 인식 정확도와 사용성을 검증한다.

> 공의 움직임 인식, 분석 항목, 영상 저장 방식 및 AI 피드백의 정확도는 아직 확정되지 않았으며 기술 검증이 필요하다.

## 6. 차별성

- **AI 경기 분석에 집중:** 고객·매출 관리 프로그램을 중심으로 경쟁하기보다 경기 분석과 실력 향상 피드백을 핵심 가치로 삼는다.
- **경기 기록을 통한 피드백:** 경기 영상을 다시 보는 것에서 그치지 않고, 분석 결과를 이용자가 플레이 개선에 활용할 수 있도록 하는 것을 목표로 한다.
- **기존 시스템과의 연동 검토:** 기존 점수판이나 관리 시스템을 모두 교체하도록 요구하기보다, 연동 가능성을 먼저 검토해 도입 부담을 낮춘다.
- **대형 기업 대상 공급:** 프랜차이즈 본사나 기존 솔루션 기업과 계약해 시범 매장에서 효과를 검증한 뒤 여러 매장으로 확대하는 전략을 추진한다.

> AI 경기 분석이 실제 경쟁 서비스에 없는 기능인지는 아직 확인되지 않았다. 경쟁사 기능 조사와 시제품 테스트를 통해 차별성을 검증해야 한다.

## 7. 사업 실행 전략: 수익 모델·장비 설치·시장 진입

### 7.1 수익 모델 — 기업 대상 B2B 판매

대형 당구장 프랜차이즈 본사와 기존 당구장 솔루션 기업을 대상으로 AI 경기 분석 기술을 공급한다.

- **본사 계약비:** 기업과 솔루션 공급 계약을 체결한다.
- **매장별 설치비:** 카메라, 영상 분석 장치 등 필요한 장비의 설치 및 초기 설정 비용을 받는다.
- **월 구독료:** AI 분석 프로그램, 경기 기록 및 영상 관련 기능의 이용료를 매월 받는다.
- **추가 기능 수익:** 추후 고급 분석이나 추가 저장 기능 등을 유료 옵션으로 제공하는 방안을 검토한다.

구체적인 가격은 장비 원가, 개발·유지관리 비용, 고객사의 지불 의사를 조사한 뒤 정한다. 본사 계약비와 매장별 비용을 어떤 방식으로 청구할지도 고객 인터뷰를 통해 검증한다.

### 7.2 장비 설치 방식

처음부터 모든 당구대에 장비를 설치하기보다, 한 대 또는 소수의 당구대에서 시범 운영을 진행한다.

1. 당구대 위쪽에 카메라를 설치해 경기 영상을 촬영한다.
2. 컴퓨터 또는 영상 분석 장치에서 공의 움직임과 경기 장면을 분석한다.
3. 분석 결과와 경기 영상을 이용자가 확인할 수 있는 프로그램으로 제공한다.
4. 기존 점수판 및 당구장 시스템과 연동할 수 있는지 확인한다.
5. 인식 정확도, 설치 비용 및 사용성을 검증한 후 설치 범위를 확대한다.

카메라 위치와 수량, 컴퓨터 사양, 조명 조건, 네트워크, 기존 장비와의 연동 방식은 아직 확정되지 않았다. 실제 당구장 환경에서 시험해 필요한 장비와 비용을 산정한다.

### 7.3 기존 서비스를 이길 핵심 전략

**당구장 관리 프로그램을 하나 더 만드는 대신, AI 경기 분석과 실력 향상 피드백에 집중한다.**

- 경기 영상을 바탕으로 이용자가 자신의 플레이를 돌아보고 개선점을 찾도록 돕는다.
- 기존 장비와 시스템을 활용할 수 있도록 연동 가능성을 검토해 전면 교체 부담을 줄인다.
- 소수 매장에서 먼저 시범 운영해 분석 정확도와 이용자 만족도를 검증한다.
- 검증된 결과를 근거로 프랜차이즈 본사 및 기존 솔루션 기업에 제안하고, 계약 후 여러 매장으로 확대한다.

경쟁 서비스보다 우수하다고 주장하기 전에 기존 제품의 AI 분석 기능과 실제 성능을 비교해야 한다. 핵심 경쟁력은 분석의 정확성, 이용자가 이해하기 쉬운 피드백, 도입 비용 및 현장 사용성으로 검증한다.

### 7.4 실행 순서

1. 당구 이용자와 당구장 관계자를 인터뷰해 분석 기능에 대한 수요를 확인한다.
2. 경쟁 서비스의 영상·AI 분석 기능을 조사한다.
3. 핵심 분석 기능의 시제품을 개발한다.
4. 소수의 당구대에서 촬영·분석 정확도와 설치 비용을 테스트한다.
5. 테스트 결과를 바탕으로 대형 기업에 시범 도입을 제안한다.
6. 성과와 지불 의사가 확인되면 매장 확대 및 정식 계약을 추진한다.

## 8. 구현 방안 (요구사항)

### 8.1 시제품(MVP) 범위

- 이번 단계의 목표는 7.4 실행 순서의 3번, **핵심 분석 기능의 시제품을 구현하고 동작을 검증하는 것**이다.
- 당구장에는 이미 큐스코 등 점수판·관리 앱이 있으므로, 새 앱을 만드는 대신 **기존 앱에 붙일 수 있는 분석 기능**으로 설계한다. 이는 6장의 "기존 시스템과의 연동 검토" 전략과도 이어진다.
- 구독·결제, 본사·매장 관리, 클라우드 확장, 기존 시스템과의 실제 연동은 시제품 검증 이후 단계에서 다루며, 이번 단계에서는 연동 구조만 설계한다.

### 8.2 전체 구조

```
녹화 영상 → 백엔드(NestJS) → Python 분석 프로그램(OpenCV) → 백엔드 → SQLite 데이터베이스 → 웹 화면(Next.js, 휴대폰 크기)
```

| 구성 | 역할 | 사용 기술 |
|---|---|---|
| 분석 프로그램 | 영상에서 공 3개(흰공·노란공·빨간공)를 찾고 궤적과 쿠션 횟수를 계산 | Python, OpenCV |
| 백엔드 | 영상 업로드, 분석 실행, 결과 저장, 웹 화면에 전달 | NestJS |
| 데이터베이스 | 경기 기록과 분석 결과 저장 | SQLite |
| 웹 화면 | 경기 리플레이, 궤적 표시, 피드백 확인 | Next.js |

### 8.3 웹으로 만든다

이용자 화면은 앱이 아닌 **웹**으로 만든다.

- **도입이 쉽다:** 이용자는 링크나 QR 코드만 열면 설치 없이 바로 볼 수 있다.
- **기능 추가 개념과 맞다:** 기존 점수판 앱은 앱 안에 웹 화면을 띄우는 방식(웹뷰)으로 이 기능을 쉽게 붙일 수 있다.
- **핵심에 집중한다:** 앱 개발 대신 영상 분석 기능에 시간을 쓴다.
- 화면은 휴대폰 크기에 맞춰 만들어 앱처럼 보이게 한다.

> 푸시 알림처럼 앱에서만 가능한 기능이 필요해지면, 웹 화면을 앱으로 감싸는 방식(PWA 또는 웹뷰 앱)으로 확장한다.

### 8.4 데이터베이스가 필요하다 — SQLite 사용

경기 기록, 궤적, 분석 결과를 저장하고 다시 보여줘야 하므로 데이터베이스가 필요하다. 설치가 필요 없고 파일 하나로 동작하는 **SQLite**를 사용한다.

**SQLite에 넣을 데이터**

| 테이블 | 저장하는 내용 |
|---|---|
| 매장 (stores) | 매장 이름 (시제품 단계에서는 시범 매장 1곳) |
| 당구대 (billiard_tables) | 어느 매장의 몇 번 당구대인지 |
| 경기 (matches) | 경기 날짜, 당구대, 참가자, 점수 |
| 이닝 (innings) | 경기 안의 이닝 번호 |
| 샷 (shots) | 소속 이닝과 순번, 시작·끝 시간, 친 공, 쿠션 횟수, 성공 여부, 실패 원인 |
| 궤적 (trajectories) | 샷마다 프레임별 공 3개의 위치 좌표 |
| 추천 경로 (recommended_routes) | 샷 시작 배치에서 계산한 참고 경로 좌표와 설명 |
| 영상 클립 (clips) | 샷별 영상 파일의 저장 위치, 시작·끝 시간 |
| 피드백 (feedback) | 샷이나 경기에 대한 분석 결과 문장 (예: "쿠션 2회, 목표 3회") |

- **영상 파일은 데이터베이스에 직접 넣지 않는다.** 영상은 폴더에 파일로 저장하고, 데이터베이스에는 파일 위치와 시간 정보만 기록한다.
- 피드백은 처음에는 쿠션 횟수, 샷 성공률 같은 **규칙 기반 통계**로 만든다. 학습된 AI 모델은 데이터가 쌓인 뒤의 확장 과제로 둔다.

### 8.5 구현 순서

1. 영상 한 장면에서 공 3개 찾기 (가장 먼저 검증할 부분)
2. 영상 전체에서 공의 궤적 추적하기
3. 샷과 쿠션 판정하기
4. 이닝별로 정리하고 샷별 영상 만들기
5. 실패 원인과 추천 경로 분석하기
6. 결과를 SQLite에 저장하고 웹 화면에서 보여주기
7. 실제 1~2시간 영상으로 전체 검증하기

> 공 인식 정확도는 조명, 공끼리 겹침, 손·큐에 가려짐에 따라 달라질 수 있으며 실제 영상으로 검증해야 한다. 공끼리 맞았는지 판단하는 득점 자동 판정은 쿠션 판정보다 어려우므로 우선순위를 낮춘다.

### 8.6 경기 영상 자동 정리와 샷 분석

이용자가 **1~2시간 분량의 경기 영상**을 올리면, 서비스가 영상을 **이닝과 샷 순서로 자동 정리**한다. 이닝은 3쿠션 대회 경기 방식에 따라 선공과 후공이 한 번씩 차례를 마치면 1이닝으로 센다. 이용자가 "몇 이닝 몇 번째 샷"을 선택하면 다음을 보여준다.

| 항목 | 내용 |
|---|---|
| 실제 경로 | 수구와 목적구가 어떻게 움직였는지 |
| 샷 영상 | 해당 샷만 잘라낸 짧은 영상 (샷 시작부터 공이 멈출 때까지) |
| 실패 원인 | 실패한 샷의 경우 첫 목적구 실패, 두 번째 목적구 실패, 쿠션 부족 등 |
| 추천 경로 | 샷 시작 때의 공 배치에서 더 나았을 경로 |

> 영상만으로는 회전과 힘을 정확히 알기 어려우므로, 시제품의 추천 경로는 공 배치와 쿠션 반사 계산에 따른 참고 경로로 제공한다. 긴 영상의 처리 시간, 사람이 당구대를 가리는 장면에서의 정확도는 실제 영상으로 검증해야 한다.
